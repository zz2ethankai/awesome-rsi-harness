## 10月18日具身增补

[RoboRSI](https://arxiv.org/html/2610.12424v1)把共享技能组织为责任清楚的任务技能图，修复限制在失败分支，并以接口后置条件和历史验证约束发布。复合技能固化减少重复模型决策。真机104轮属于有人引导的开发过程；冻结库的LIBERO-Plus测试与在线更新成绩必须分开。其依赖局部性分析需要完整依赖图等假设，不构成无回归保证。

[RoboFoundry](https://arxiv.org/html/2609.32862v1)共同更新context和skill系统，并将任务级修复抽象成通用规则。它已检验通用规则如何影响其他任务的修复提议，因此不能一概归为只有最终技能增长。但§2.3的promotion是在历史轨迹上提出修复并由模型评分，不等于所有候选经历独立物理复执行。多底座分别演化也不同于同一个冻结改进器跨底座迁移。它是改进经验路径的关键近邻，不能仅凭框架名称认定严格递归已得到完整验证。

对研究路线的影响：局部归因修复、历史回归检查和任务修复晋升为通用规则均已有先例。后续应核对修复评分与真实执行效用、误晋升和负迁移，以及完整成本下冻结规则的迁移收益。RoboRSI有公开实现；RoboFoundry官方仓库目前仍列代码发布TODO，不把仓库存在当作实现已开放。

| --- | --- | --- |
| 持久改进、共同训练、元改进被混称RSI | 会把普通自训练、反思和研究自动化也当成改进机制变强 | 分开记录更新对象、继承路径、改进器变化及其效果证据 |
| 清单过度集中最近一周HF | 新标题多，却缺少解释递归本身的参照 | 补STOP/DGM的代码自改和SEAL的学习更新策略；GEPA作为固定优化器边界对照 |

| benchmark、评测研究、verification都被读成RSI方法 | “能测”“能判”不等于“自己学会更好地改进” | 逐篇增加role；例如Rethinking是evaluation study，GDPevo是benchmark |
| 改进器变化只按源码是否重写判断 | 会漏掉学到的更新策略和改进经验，也会高估任意代码改动 | 分开代码自改、学习更新策略、改进记忆和普通artifact更新，不作为成熟度排名 |

“未建立证据”不表示机制不存在。分类是本清单的操作约定；不同survey对RSI使用宽窄不同，不替作者统一改定义。

## 2. 定义和系统边界

把系统状态写为：

`S_t = (model, harness, knowledge, data, trainer, improver)_t`

一轮改进可以分解为：

`执行 → 收集反馈 → 诊断 → 提案 → 试验 → 选择 → 接受/拒绝 → 持久保留`

这不是要求每篇都有独立八个模块，而是检查信息流。关键问题是：什么变化被保留、后来谁实际使用它、它是否还影响下一轮改进。

需要区分三个命题：

1. 当前任务修好了：一次重试、答案修订或规划恢复。
2. 后续执行变好了：保留权重、技能、记忆或harness后，在新任务或后续实例上更好。
3. 后续改进过程变好了：保留的变化使以后怎样选经验、提案、诊断、训练或接受更新更有效。

三个命题的证据不能互相替代。第3点不要求必须修改底层LM权重或Python源码；一个学习到的self-edit策略也可能承担该角色。反过来，代码变了不保证改进能力提升。

[Prism survey §3](https://arxiv.org/html/2610.14625v1)给出更新对象、组织方式、时间/范围、反馈/选择多个维度；[D2I框架](https://www.preprints.org/manuscript/202608.0051/v1)把改进机制Imp单列；[自治中心survey](https://arxiv.org/html/2609.11873v1)强调改进责任的自治范围。这些维度互补，不可拼成一套通用L1–L5。

## 3. 内容体系应该有七条轴

### 更新对象

| 对象 | 内容 | 当前参照 |
| --- | --- | --- |
| Model | 执行策略、critic、世界模型等参数 | Terminal-RSI、ReTerm、VLAW |
| Context | prompt、规则、观察组织 | GEPA、VIEWCRAFT |
| Memory | 反思、研究状态、失败/经验记录 | ReHarness、SwarmRSI |
| Skills | 可检索程序、SOP及恢复策略 | Cortex、CarryOn、GDPevo参评技能 |
| Harness | 执行循环、工具、控制代码及其配置 | DGM、Harness²、EMHO |
| Learning System | 数据、任务/环境、训练和反馈程序 | AutoSFT、ClawLoop、WorkRover、CoDA |
| Improver | 生成/选择更新的代码、参数化策略或持久改进知识 | STOP、SEAL、RSIPO、Harness² |

对象允许多标签。Improver是功能角色，不是某种文件类型：一段prompt、一个神经网络或一份库都可能参与改进，但必须核实其实际使用路径。首页把Context并入广义Harness、Memory与Skills合并，只是为了浏览简洁。

### 改进机制

应覆盖失败诊断、经验提炼、候选生成、变异与重组、搜索与课程、训练更新、验证与接受、回归保护。它们是算法部件，不应与“机器人”“在线”混成并列类别。

### 反馈

区分环境真实结果、可执行测试、人类纠正、模型判断、学习进展代理和世界模型预测。记录反馈由谁生成、谁能修改、是否与最终验收独立。外部反馈不使系统失去自改进身份；自评分也不使它自动获得可靠性。

### 改进组织

区分同一模型、独立teacher/editor、多agent协作，以及线性、树、档案/图搜索。多个agent或两个组件相互训练都不单独构成元改进证据。

### 时间和继承范围

区分离线开发后冻结、流式在线、离线到在线；记录同实例、同任务族、新来源、新领域等迁移范围。另记更新频率、权重是否重置、经验是否跨任务保留。

### 证据

分开最终执行收益、学习/改进效率、保留与负迁移、安全与成本。统计上分开task、来源簇、技能生成运行和训练seed。一个checkpoint大量rollout不能替代多次独立改进过程。

### 应用

软件、企业工具任务、自动研究、GUI、多模态、具身机器人是应用标签，不是算法对象。导航指令自训练、真机控制和抽象ALFWorld交互不能因为都叫embodied就直接比较。

## 4. 四类递归路径不能混用

以下是机制类型，不是能力等级；一个系统可以落在多个类型。

### 固定改进器更新执行系统

[GEPA](https://arxiv.org/pdf/2507.19457v2)用反馈更新prompt和候选池，但核心反思/选择算法固定。[ReHarness §3.2](https://arxiv.org/html/2610.12668v1)修订持久反思，改变后续上下文，不因此证明记忆更新算法被改写。两者是重要的自改进参照，不能因外层固定就排除整个研究方向，也不能直接宣称元优化成立。

### 改进经验跨轮保留

[Harness²](https://arxiv.org/html/2610.14224v1)保留指导未来编辑的改进库。[SwarmRSI](https://arxiv.org/html/2610.20431v1)继承假设、候选程序和实验证据。改进策略可以通过这种知识积累发生适应，但它与重写搜索算法不同。应比较更新库、冻结库和等量原始经验的后续改进收益。

### 学习更新策略

[SEAL §3](https://arxiv.org/html/2506.10943v2)用更新后任务效用训练self-edit生成策略，提供“学会怎样更新”的直接路径。[RSIPO §3.2](https://arxiv.org/html/2610.15772v1)按技能条件化重放收益优化技能生成并调整teacher信任，而不只是更新静态技能库。两者的外层训练规则仍固定，不能据此推出不受限的开放域递归改进。

### 自修改的改进程序

[STOP Algorithm1](https://arxiv.org/pdf/2310.02304v3)直接以improver自身为优化对象，用下游算法优化效用评价新improver。[DGM §3–4及AppendixA](https://arxiv.org/html/2505.22954v3)让保留的编码agent参与下一轮self-modify，并设置固定meta-agent对照。它们比一般反思更直接触及递归路径，但仍受固定LM、任务域、外层搜索和资源限制。STOP作者所说“不完整RSI”还涉及其自身系统边界，不能删去。

## 5. 本轮重新审视的四篇

### RSIPO

过去只把它写成skill-policy co-evolution过于粗糙。方法中对生成技能施加下游重放收益，明确学习技能生成能力；因此它不应只和普通循环训练放在一起。但评估“学会改进”还要分离额外重放、执行策略变强和技能生成变强的贡献。已将其编码为learned update policy，不等于自动授予通用RSI等级。[正文](https://arxiv.org/html/2610.15772v1)

### AutoSFT

每轮从同一基座重训，继承的是数据池和配方，而非学生checkpoint。重置权重不表示没有持久改进；真正要追问的是研究agent及其数据决策机制是否更新。作者每配置只运行一次search，重复评价不覆盖搜索过程方差。[§2.1和局限](https://arxiv.org/html/2610.22194v1)

### MLExpert

它训练了机器学习工程策略，能优化外部算法/scaffold；scaffold实验区分开发年份和冻结终测年份。但这不能单独证明研究策略以自身为对象持续改进。保留为supporting method，不从名称中的AI4AI/RSI动机推断闭环已实现。[AppendixD.3](https://arxiv.org/html/2610.22344v1)

### SwarmRSI

主继承对象是研究状态，不是自身runtime源码，所以改放Memory and Skills。源到held-out任务的继承测试有价值；但更多代也积累更多源任务，仍要控制经验量，才能把结果解释为更有效的改进过程。[方法和AppendixC.2](https://arxiv.org/html/2610.20431v1)

## 6. 评测体系必须拆开

| 问题 | 合适的实验 | 不能替代它的指标 |
| --- | --- | --- |
| 更新后更会执行吗 | 冻结新旧版本，在相同独立任务和预算下配对测试 | 开发集best score |
| 更会学习吗 | 相同起点与适应预算，比较学习曲线/最终收益 | 仅比较最终checkpoint |
| 更会生成改进吗 | 固定executor，比较新旧improver产生的更新效用 | 仅展示更复杂提案 |
| 记忆是否真的帮助改进 | 冻结/更新库、等量原始经验、相同新任务 | 更多历史经验自然带来的涨分 |
| 保留规则安全吗 | 独立接受集、历史回归和严重错误约束 | 自己改grader后自评分上升 |
| 预算效率更好吗 | 搜索、生成、反馈、训练、评价、重试、人工全部分账 | 单次执行token更少 |

一个有用的元改进目标量是：在兼容的共同初始状态、目标任务分布和适应预算B下，使用新improver与旧improver适应后的独立价值之差。该比较还要报告获得新improver的前期成本。

若executor和improver同时更新，尽量做旧/新executor × 旧/新improver的交叉对照，并检查交互。存在接口/参数不兼容时，不能假装四个组合都可实现；应限定比较范围。

### GDPevo放在哪里

[GDPevo](https://arxiv.org/html/2608.03764v1)直接测试训练经验提炼成技能后，是否帮助同环境内重新组合规则的测试任务。它能支撑“技能获得了迁移效用”，不单独支撑“skill creator自我演化”。`acc@3`是三次平均rubric评分，不是pass@3或严格全部完成率；技能生成成本单列。组内规则迁移和跨领域迁移也必须分开。

### DGM新增的成本警示

[v3成本估计](https://arxiv.org/html/2505.22954v3)给出SWE-bench主运行约22,000美元，两个消融基线各约10,000美元。固定meta-agent对照对递归路径有参考价值，但不能把全部差值都称为“等成本下元改进”的因果效应。保持开放探索、采样/反馈预算一致的补充对照仍重要。

### 支撑类工作

Doc2Harness主要测harness工程契约；EmbodiedCLBench主要测持续学习与组合；SWE-Duel主要测动态对抗出题；Rethinking是预算与泛化的评测研究。Verifier Hardening、CLIFT和置信校准用于反馈可靠性，不能统一计作已验证的递归改进方法。RSIGym仍是摘要核查，需继续核指标定义。

## 7. 具身方向的闭环

具身主线应检查：失败发生在哪个物理因素 → 怎样产生对照/课程 → 如何验证世界模型与奖励 → 怎样训练策略 → 哪些程序与经验被继承 → 下一轮生成决策是否改善。

CoDA对应诊断、生成/训练程序和策略共同演化；VLAW对应世界模型与策略共同更新；CarryOn对应持久记忆和恢复技能，固定shield本身不是学习；RSI-Nav对应同步语言-动作自训练；EMHO对应冻结模型外的harness优化。它们不是同一种RSI，也不能放在同一成功率排行榜。

至少要检查仿真到真实、未见接触与因素组合、总机器人交互、安全代价、独立物理验收，以及旧能力保留。世界模型更逼真、奖励更高和真实策略更强是三个不同命题。[CoDA](https://arxiv.org/html/2610.22362v1)、[VLAW](https://arxiv.org/html/2602.12063v2)、[CarryOn](https://arxiv.org/html/2610.21453v1)

## 8. 尚未补全的版图

当前集合仍偏近一周HF。新增四项参照只修复了部分骨架，不构成完整系统综述。应按以下顺序补读，而非自动批量导入：

| 缺口 | 后续候选/检索入口 | 当前状态 |
| --- | --- | --- |
| 理论自指与元学习 | Gödel Machine、learned optimizer、meta-RL | 作为概念来源，本轮未逐篇核正式理论 |
| 长期记忆与技能早期工作 | Reflexion、ExpeL、Voyager | 基础脉络待补，不把二手引用当正文核查 |
| 工作流与prompt优化 | AFlow、ADAS、Promptbreeder、TextGrad | 应与GEPA区分固定搜索与可变improver |
| 经验/课程与开放环境 | Actor-Curator、CURATE、PACE、POET等 | 当前仓库未全量纳入，不因其他笔记读过就假装本索引完成覆盖 |
| 进化原生benchmark | EvoAgentBench、SkillFlow、SEA-Eval、BenchTrace | 从GDPevo原文引用回溯，版本和协议待一手核验 |
| 自修改安全 | 权限隔离、接受门、污染/后门、回滚与外部副作用 | 当前verification只覆盖一部分，需独立专题 |

不按标题关键词计数“全领域有多少严格RSI”；当前role和meta_path只是选定文献集的可复核编码。未核项不会被计成否定证据。

## 9. 对Awesome的落地

首页继续保留Surveys、Methods、Benchmarks、Verification、Resources；不恢复解释性caption。细粒度对象、反馈、继承路径、角色和证据缺口放到结构化审计及矩阵中。SwarmRSI调整主位置；补四项基础参照；保留原32项，避免为了让目录好看而删掉反例或支撑研究。
